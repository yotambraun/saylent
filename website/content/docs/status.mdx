This checks **the maintainer's own provider keys**, not yours. It exists so you
can see, before you spend anything, which providers currently answer with the
registry's default models (`packages/engine/src/models.ts`) - not a claim
about your own account, quota, or billing status.

A weekly [GitHub Action](https://github.com/yotambraun/saylent/actions/workflows/provider-status.yml)
sends one minimal question to every configured provider and writes the result
here (`website/public/status/status.json`, committed to `main`). It costs
about $0.05 per run. You can also run it yourself against your own keys:

```bash
npx tsx --tsconfig scripts/tsconfig.json --env-file=.env.local scripts/provider-status.ts
```

## What this does not tell you

- **Not your keys.** A green row here says the maintainer's key and the
  registry default worked this week - it says nothing about your own
  account's quota, billing, or region.
- **Not an SLA.** One question, once a week. A provider having a bad five
  minutes at another time of day would not show up here.
- **Not model quality.** This checks that the API call succeeds and returns
  text with the current registry default model - see
  [Configuration](/docs/configuration) for how to override any model, and
  `saylent models` for what your own deployment is actually using.

See [What it costs](/docs/costs) for the cost of a real audit, and
[Configuration](/docs/configuration) for the full `MODEL_*` override list.
